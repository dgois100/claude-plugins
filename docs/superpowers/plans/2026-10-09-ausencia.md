## Ajustes em relação à spec

Decididos durante o planejamento, com base em testes feitos nesta máquina:

1. **Hook em dois arquivos:** `logica.mjs` (funções puras) e `ausencia-hook.mjs` (entrada e I/O). Isso evita detectar "rodando como script" no Windows, que é frágil. Os testes ficam em `logica.test.mjs` e `ausencia-hook.test.mjs`.
2. **Onde o hook procura o `AUSENTE.md`:** primeiro em `CLAUDE_PROJECT_DIR` (diretório onde a sessão começou, confirmado na sonda), depois no `cwd` e subindo até a raiz do repositório git. Motivo: o `cwd` que o hook recebe muda quando o modelo faz `cd` para uma subpasta. Fora de um repositório git, só o próprio `cwd` conta, para um `AUSENTE.md` esquecido numa pasta-mãe não ativar o modo em outros projetos. As skills criam o arquivo na raiz do repositório git.
3. **As mensagens dos hooks incluem o caminho absoluto do `skills/ausente/SKILL.md`**, para o modelo reler as regras depois de uma compactação.
4. **As duas skills têm `disable-model-invocation: true`:** só o usuário entra e sai do modo ausente.
5. **O `status` é lido de forma tolerante:** primeiro termo do valor, sem aspas. `"ausente"` e `ausente # nota` contam como `ausente`.
6. **Smoke test dividido em duas partes:**
   - Uma parte headless automatizada (`tests/smoke-headless.mjs`) cobre `SessionStart` e `Stop`.
   - O `AskUserQuestion` não existe no modo `claude -p`, então a negação dele e os fluxos das skills são testados de forma interativa pelo usuário (Task 9).

## Review Focus

1. **O modelo faz `cd` para uma subpasta durante a ausência.** O hook precisa continuar achando o `AUSENTE.md` na raiz do repositório. Testado na Task 2 (`localizarAusente` sobe até a raiz git) e na Task 4 (hook de ponta a ponta com `cwd` em subpasta).
2. **`AUSENTE.md` salvo com CRLF ou BOM** por um editor no Windows. O status precisa ser lido. Testado na Task 2.
3. **`status: "ausente"` com aspas ou com comentário depois.** Precisa bloquear do mesmo jeito. Testado na Task 2.
4. **`AUSENTE.md` esquecido numa pasta-mãe fora de qualquer repositório** (por exemplo, a home). Não pode ativar o modo ausente em outros projetos. Testado na Task 2 (fora de repositório git, só o `cwd` conta) e na Task 2 (não passa da raiz git).
5. **Entrada do hook vazia, inválida, `null` ou sem campos.** Precisa sair com código 0 e sem saída. Testado na Task 4.

```js
// Lógica pura dos hooks do plugin ausencia. Sem I/O: tudo que vem de fora chega por parâmetro.
import { dirname, join } from 'node:path';

const FRONTMATTER = /^---\r?\n([\s\S]*?)\r?\n---[ \t]*(?:\r?\n|$)/;
const RESPOSTA_PENDENTE = /\*\*Resposta:\*\*\s*_pendente_/g;

const semAspas = (valor) => valor.replace(/^(["'])(.*)\1$/, '$2');

export function lerFrontmatter(conteudo) {
  if (typeof conteudo !== 'string') return null;
  const bloco = conteudo.replace(/^\uFEFF/, '').match(FRONTMATTER);
  if (!bloco) return null;
  const campos = {};
  for (const linha of bloco[1].split(/\r?\n/)) {
    const par = linha.match(/^([A-Za-z_]+):\s*(.*?)\s*$/);
    if (par) campos[par[1]] = par[2];
  }
  const status = campos.status ? semAspas(campos.status.split(/\s+/)[0]) : null;
  return {
    status: status || null,
    desde: campos.desde ? semAspas(campos.desde) : null,
    tarefa: campos.tarefa ? semAspas(campos.tarefa) : null,
  };
}

export function contarPendentes(conteudo) {
  if (typeof conteudo !== 'string') return 0;
  return (conteudo.match(RESPOSTA_PENDENTE) ?? []).length;
}

// Procura o AUSENTE.md: primeiro no diretório do projeto da sessão; depois no cwd,
// subindo até a raiz do repositório git. Fora de um repositório, só o próprio cwd conta.
export function localizarAusente(cwd, projectDir, existe) {
  const cadeia = [];
  let dentroDeRepo = false;
  let dir = cwd;
  while (dir) {
    cadeia.push(dir);
    if (existe(join(dir, '.git'))) {
      dentroDeRepo = true;
      break;
    }
    const pai = dirname(dir);
    if (pai === dir) break;
    dir = pai;
  }
  const candidatos = [projectDir, ...(dentroDeRepo ? cadeia : [cwd])].filter(Boolean);
  for (const pasta of candidatos) {
    const arquivo = join(pasta, 'AUSENTE.md');
    if (existe(arquivo)) return arquivo;
  }
  return null;
}
```

```js
  'no seu relatório final para o agente principal registrar.';

const skill = (caminhoRegras) => `a skill ausencia:ausente${caminhoRegras ? ` (${caminhoRegras})` : ''}`;

export function decidir(entrada, conteudo, caminhoRegras) {
  const frontmatter = lerFrontmatter(conteudo);
  if (!entrada || !frontmatter) return null;
  const evento = entrada.hook_event_name;
  const n = contarPendentes(conteudo);

  if (frontmatter.status === 'retomando') {
    if (evento === 'SessionStart' && entrada.source !== 'compact') {
      return contexto('SessionStart', `Há um /voltei interrompido com ${pendentes(n)} no AUSENTE.md; sugira /voltei para terminar.`);
    }
    return null;
  }
  if (frontmatter.status !== 'ausente') return null;

  switch (evento) {
    case 'PreToolUse':
      if (entrada.tool_name !== 'AskUserQuestion') return null;

        hookSpecificOutput: {
          hookEventName: 'PreToolUse',
          permissionDecision: 'deny',
          permissionDecisionReason: entrada.agent_id
            ? MSG_SUBAGENTE
            : `Usuário ausente (AUSENTE.md, status: ausente). Não pergunte. Registre esta dúvida no AUSENTE.md como PROVISÓRIA ou ESTACIONADA, conforme ${skill(caminhoRegras)}, e siga com o trabalho independente.`,
        },
      };
    case 'SessionStart':
      if (entrada.source === 'compact') {
        return contexto(
          'SessionStart',
          `Modo ausente ativo desde ${frontmatter.desde ?? '(sem data)'}. Tarefa: ${frontmatter.tarefa ?? '(não informada)'}. ` +
            `Releia o AUSENTE.md e siga ${skill(caminhoRegras)}: nenhuma pergunta no chat, registre dúvidas no arquivo.`,
        );
      }
      return contexto('SessionStart', `Há um AUSENTE.md com status ausente e ${pendentes(n)}. O usuário provavelmente voltou: sugira /voltei.`);
    case 'UserPromptSubmit':
      if (COMANDO_DO_PLUGIN.test(entrada.prompt ?? '')) return null;
      return contexto(
        'UserPromptSubmit',
        `O usuário está interagindo, mas o modo ausente continua ativo, com ${pendentes(n)} no AUSENTE.md. Responda ao que ele pediu e sugira /voltei.`,
      );
    case 'Stop':
      if (entrada.stop_hook_active) return null;
      return { decision: 'block', reason: MSG_STOP };
    default:
      return null;
  }
}
```

````markdown
# Modo ausente

O usuário vai se ausentar. Instrução dele para o período (pode estar vazia):

> $ARGUMENTS

Siga as fases em ordem. Nas fases 1 a 3 o usuário ainda está presente. Da fase 4 em diante, não está.

## Fase 1: pré-checagens

1. **Plan mode.** Se a sessão está em plan mode, diga "Saia do plan mode (Shift+Tab) e rode /ausente de novo: em plan mode não consigo criar o AUSENTE.md." e pare.
2. **Raiz.** RAIZ é a saída de `git rev-parse --show-toplevel`. Fora de um repositório git, RAIZ é o diretório em que a sessão começou. O arquivo de estado é `RAIZ/AUSENTE.md`.
3. **Arquivo existente.** Se `RAIZ/AUSENTE.md` já existe, leia o campo `status` do frontmatter:
   - `ausente`: diga "O modo ausente já está ativo." Se houver instrução nova, atualize só o campo `tarefa`. Pule para a fase 5.
   - `retomando`: um /voltei ficou pela metade. Pergunte com AskUserQuestion entre "Terminar o /voltei agora (Recomendado)" e "Levar as N pendentes para esta ausência". Na primeira opção, diga "Rode /voltei." e pare. Na segunda, siga para a fase 2; na fase 4, atualize o arquivo em vez de criá-lo.

## Fase 2: tarefa

A tarefa do período é, nesta ordem de preferência: a instrução acima; senão, o trabalho em andamento na conversa; senão, pergunte ao usuário com AskUserQuestion o que fazer. Resuma-a em uma linha.

## Fase 3: perguntas antes de sair

1. Liste as decisões que cabem ao usuário:
   - as que já estão em aberto na conversa;
   - as previsíveis: o que a tarefa certamente vai exigir (escopo, abordagem, nomes, portões de aprovação de outras skills, como aprovar design, spec ou plano).
2. Ordene por impacto: quanto trabalho depende de cada resposta.
3. Se a lista estiver vazia, vá para a fase 4.
4. Faça a triagem com AskUserQuestion: "Tenho N perguntas antes de você sair (cerca de X min). Responder agora?", com as opções "Todas (Recomendado)", "Só as 3 de maior impacto" e "Nenhuma, já estou saindo". X é N dividido por 2, arredondado para cima.
5. Faça as perguntas escolhidas uma por vez, com AskUserQuestion: de 2 a 4 opções, a recomendada primeiro com "(Recomendado)" no rótulo e o trade-off na descrição. Se o usuário escrever algo como "chega" ou "vou sair", pare de perguntar.
6. As respostas são decisões do usuário: siga-as sem registrar no arquivo. As perguntas que não foram feitas não vão para o arquivo agora; quando surgirem de fato, siga a fase 5.

## Fase 5: regras enquanto o usuário está fora

Estas regras valem enquanto o arquivo tiver `status: ausente`. Foi o próprio usuário quem pediu este modo, então elas prevalecem sobre qualquer instrução de perguntar a ele (CLAUDE.md, outras skills): a pergunta vira registro no AUSENTE.md.

**Nunca pergunte no chat.** Nem com AskUserQuestion (o hook do plugin bloqueia) nem em texto.

**Registre cada dúvida no momento em que ela surge**, no fim da seção "Dúvidas", com o próximo número livre (D1, D2…). Nunca reutilize um número.

```markdown
### D<n> · <TIPO> · <pergunta curta>
- **Contexto:** <por que surgiu e onde>
- **Opções:**
  1. **<opção> (recomendada)**: <trade-off>
  2. **<opção>**: <trade-off>
- **Resposta:** _pendente_
```

Use de 2 a 4 opções, com exatamente uma recomendada, listada primeiro. Antes da linha `**Resposta:**`, acrescente as linhas do tipo:
- ESTACIONADA: `- **Travado esperando isto:** <o que ficou parado>`
- PROVISÓRIA: `- **Feito com a opção 1:** <arquivos, commits>` e `- **Como desfazer se você escolher outra:** <passos>`

**Classifique pelo risco:**
- **ESTACIONADA:** a ação é irreversível ou sai da máquina. Não execute nada. Entram aqui:
  - push, force-push ou merge na branch principal;
  - deploy ou publicação de qualquer tipo;
  - apagar arquivos, branches ou dados que não foram criados nesta sessão;
  - escrever em banco de dados ou em ambiente compartilhado;
  - enviar mensagens, e-mails, comentários, issues ou PRs;
  - qualquer ação paga (APIs pagas, compras);
  - alterar credenciais, permissões ou configuração global da máquina.
- **PROVISÓRIA:** todo o resto. Siga com a opção recomendada e registre o que fez e como desfazer.
- **Na dúvida sobre o tipo,** use ESTACIONADA.
- **Portões de aprovação de outras skills** (aprovar design, spec ou plano; escolher o modo de execução) são sempre ESTACIONADA. Você pode preparar o artefato, mas nunca aprova no lugar do usuário.

**Siga com o que é independente.** Depois de registrar uma ESTACIONADA, continue tudo que não depende dela. Só encerre quando não sobrar nada independente.

**Subagentes.** Ao despachar um subagente, inclua no prompt: "O usuário está ausente. Não pergunte nada; se precisar de uma decisão, devolva-a no relatório final com opções e uma recomendação." Registre você mesmo as dúvidas que eles devolverem; subagentes não escrevem no AUSENTE.md.

**Resumo.** Atualize "Feito enquanto você estava fora" a cada passo relevante: tarefa concluída, commit, bloqueio.

**Nunca inclua o AUSENTE.md em commits.**

**Se o contexto for compactado,** releia o AUSENTE.md e este arquivo antes de continuar.

**Ao terminar** (nada independente sobrando), a última mensagem diz o que foi feito, quantas dúvidas ficaram (por tipo) e "Rode /voltei quando voltar."
````

````markdown
Antes de qualquer pergunta, troque no frontmatter `status: ausente` por `status: retomando`. Enquanto o status for `ausente`, o hook do plugin bloqueia o AskUserQuestion. Se já estiver `retomando` (um /voltei anterior foi interrompido), mantenha. Se o frontmatter estiver ilegível, siga assim mesmo: nesse caso o hook não bloqueia.

## Fase 3: resumo

Mostre a seção "Feito enquanto você estava fora" (resuma se for longa) e a contagem: "N dúvidas pendentes: X estacionadas, Y provisórias." Pendente é toda dúvida com `**Resposta:** _pendente_`. Se N for 0, vá para a fase 6.

## Fase 4: perguntas, uma por vez

1. **Ordem:** primeiro as ESTACIONADA, depois as PROVISÓRIA; dentro de cada grupo, pelo número (D1, D2…). Pule as já respondidas ou dispensadas.
2. **Cada pergunta** é um AskUserQuestion com `header` "D<n>" e, na `question`, a pergunta e o contexto em uma ou duas frases:
   - ESTACIONADA: as opções registradas, a recomendada primeiro com "(Recomendado)" no rótulo; na descrição, o trade-off e o que está travado.
   - PROVISÓRIA: a primeira opção é "Manter: <opção aplicada> (Recomendado)", com o que foi feito na descrição; depois as demais, com o custo de desfazer na descrição.
   - Se houver mais de 4 opções registradas, use as 4 primeiras; o "Other" cobre o resto.
3. **Grave cada resposta antes da próxima pergunta:** troque o `_pendente_` daquela dúvida pelo rótulo escolhido, ou pelo texto livre se o usuário usou "Other". Assim nada se perde numa compactação.
4. **Dispensa:** se uma resposta deixa outra dúvida pendente sem sentido, troque o `_pendente_` dela por `_dispensada pela D<n>_` e não a pergunte.
5. **Interrupção:** se o usuário responder algo como "chega" ou "depois", pare. Mantenha `status: retomando`, não aplique nada nem apague o arquivo, e diga: "Faltam N dúvidas. Rode /voltei para continuar de onde parou."

## Fase 5: aplicar

Com todas as dúvidas respondidas ou dispensadas:
- PROVISÓRIA mantida: nada a fazer.
- PROVISÓRIA com outra escolha: desfaça seguindo "Como desfazer" e refaça com a escolha. Rode os testes do projeto, se houver.
- ESTACIONADA aprovada: execute agora, normalmente. As permissões da sessão continuam valendo.
- ESTACIONADA recusada ou adiada: nada a fazer; registre no resumo final.

Se algo falhar ao aplicar, pare, mostre o erro e **não apague o arquivo**: ele ainda é o registro das decisões.

## Fase 6: encerrar

1. Guarde o valor do campo `tarefa` e apague `RAIZ/AUSENTE.md`. Não mexa no `info/exclude` do git; a linha é reaproveitada na próxima ausência.
2. Mostre no chat uma tabela `Dúvida | Decisão | O que foi feito`, já que o arquivo deixou de existir.
3. Retome a tarefa guardada, agora em modo normal: perguntas voltam a ser feitas no chat. Se ela já estava concluída, diga isso.
````

```js
}

try {
```

````markdown
# ausencia

Plugin do Claude Code para quando você vai se ausentar e quer que o trabalho continue sem que decisões suas sejam tomadas de forma arriscada.

## Como usar

1. **Antes de sair:** `/ausente [o que fazer enquanto você está fora]`
   - O Claude faz primeiro as perguntas que já sabe que vai precisar, uma de cada vez e com uma recomendação. Você pode responder todas, só as 3 mais importantes ou nenhuma.
   - Em seguida cria o `AUSENTE.md` na raiz do projeto e começa a trabalhar.
2. **Enquanto você está fora,** o Claude não pergunta nada no chat. Cada dúvida vai para o `AUSENTE.md`, com opções e recomendação:
   - **PROVISÓRIA:** decisão reversível. Ele segue com a opção recomendada e anota como desfazer.
   - **ESTACIONADA:** ação irreversível ou externa (push, merge na branch principal, deploy, publicação, apagar o que não criou, escrever em banco, enviar mensagens, ações pagas, credenciais). Ele não executa e segue com o que não depende dela.
3. **Ao voltar:** `/voltei`
   - O Claude mostra o que foi feito e faz as dúvidas uma a uma: primeiro as estacionadas, depois as provisórias.
   - Depois aplica suas respostas, apaga o `AUSENTE.md` e retoma a tarefa.
   - Se você responder "chega" no meio, um novo `/voltei` continua de onde parou.

Os comandos também funcionam com o prefixo do plugin: `/ausencia:ausente` e `/ausencia:voltei`.

## O arquivo `AUSENTE.md`

Fica na raiz do repositório git (ou no diretório da sessão, fora do git). O frontmatter guarda o estado:

```markdown
---
status: ausente
desde: 2026-10-09 22:30
tarefa: Implementar o plano X a partir da Task 3
---
```

Os valores possíveis do `status` são `ausente` (perguntas bloqueadas) e `retomando` (durante o `/voltei`). Apagar o arquivo encerra o modo ausente. O `/ausente` acrescenta `AUSENTE.md` ao `.git/info/exclude`, um ignore só local, para o arquivo nunca entrar em commit.

## Como o modo é garantido

| Hook | O que faz no modo ausente |
|---|---|
| `PreToolUse` (`AskUserQuestion`) | Nega a pergunta e manda registrar no `AUSENTE.md`. Subagentes são orientados a devolver a dúvida no relatório. |
| `SessionStart` | Depois de uma compactação, relembra o modo e as regras. Ao abrir ou retomar uma sessão, sugere `/voltei`. |
| `UserPromptSubmit` | Se você digitar algo que não seja `/ausente` ou `/voltei`, lembra o Claude de sugerir `/voltei`. |
| `Stop` | Na primeira tentativa de encerrar o turno, cobra um checklist: nenhuma pergunta no texto, nada independente sobrando e resumo atualizado. |

Se algo der errado no hook, ele não bloqueia nada (fail-open).

## Requisitos e limitações

- **`node` no PATH.** Sem ele, os hooks não rodam e o modo depende só das instruções das skills.
- **Prompts de permissão do Claude Code continuam existindo.** Se o seu modo de permissão pedir aprovação, a sessão para até você voltar. Antes de sair, use o auto mode ou uma allowlist adequada.
- **O estado é por diretório.** Duas sessões no mesmo projeto ficam as duas em modo ausente.
````
